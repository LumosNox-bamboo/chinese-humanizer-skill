# 修改报告格式

完成中文文档去 AI 腔修改后，默认输出一份**简版修改报告**。报告用于解释编辑决策，不用于判断文本是否由 AI 生成，也不应包含“AI 检测通过率”之类结论。

## 默认简版

建议控制在 5–10 行：

```markdown
### 修改报告
- 主要问题：强行转折 3 处；“逐步/持续/进一步”重复偏多；2 个段落存在结尾升华。
- 主要处理：删除或改写机械转折，压缩抽象总结，把部分“沉淀/协同/形成”改成具体动作。
- 代表性修改：`核心竞争力不是 A，而是 B` → `核心竞争力来自 B`。
- 保留内容：事实、数据、术语、引用和必要的逻辑关系未改。
- 人工确认：第 X 段仍保留“生态”，因为该词在此处指明确的合作体系。
```

如果没有值得人工确认的项目，可以省略最后一项。

## 详细版

用户明确要求“详细报告 / 修改说明 / 对照报告”时，可按下面结构输出：

```markdown
# 修改报告

## 1. 总体情况
- 文体：商业计划书 / 报告 / 学术 / 其他
- 修改目标：降低模板化 AI 腔，保留事实与专业度
- 主要风险：强行转折、连接词密度、抽象词、段落结构、结尾升华

## 2. 主要修改类型
| 类型 | 原文特征 | 处理方式 | 数量/代表位置 |
|---|---|---|---|
| 强行转折 | 不是……而是…… | 改为直接陈述 | 3 |
| 高频修饰 | 逐步、持续、进一步 | 删除或合并 | 8 |
| 抽象表达 | 沉淀能力、构建生态 | 改成具体动作/结果 | 5 |
| 结构问题 | 连续三段式总结 | 拆句或取消升华 | 2 段 |

## 3. 代表性修改
- 原：……
- 改：……
- 原因：……

## 4. 保留项
说明哪些专业术语、逻辑转折或行业表达虽然命中规则，但因准确性需要而保留。

## 5. 修改后仍建议人工确认
只列真正需要作者判断的内容，例如语气强弱、商业主张是否过度、行业术语是否符合内部习惯。
```

## 报告原则

- 不逐句解释所有修改，避免报告比正文更长。
- 优先报告“模式”，不是堆砌改了多少个字。
- 不声称文本因此“更像真人”或“能够绕过检测”。
- 如果运行了扫描脚本，可报告前后高风险模式数量变化，但必须注明这是**启发式文本指标**，不是作者身份判断。
